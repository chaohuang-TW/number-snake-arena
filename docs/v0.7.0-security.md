# v0.7.0 套件安全修補查核

查核日期：2026-10-01。依使用者附條件正式發布授權，在 PR 分支限定升級 Vite／Vitest 相依鏈、正式根版號及 Node／CI；沒有修改玩法、Phaser 架構、正式 main、tag 或 Pages。下列是本次安全修補階段的實際結果，正式 RC_SHA／RELEASE_SHA 的完整驗收須另以凍結後證據核對。

## 實際 audit 與版本

修補前 `npm audit --json` **exit 1**：5 個受影響套件（3 moderate、1 high、1 critical），去重為6個GHSA公告。修補後另行執行相同完整 audit，**exit 0，0 vulnerabilities**；沒有尚未處置的 audit 公告或新增 high／critical。結果只代表本次 registry audit 的查核範圍，不能推論軟體絕對安全。

| 套件 | 修補前 lockfile | 修補後 lockfile | 處理方式 |
|---|---|---|---|

執行前重新讀取 [Vite 6.4.3 registry](https://registry.npmjs.org/vite/6.4.3)、[Vitest 4.1.11 registry](https://registry.npmjs.org/vitest/4.1.11)、[mocker registry](https://registry.npmjs.org/@vitest%2fmocker/4.1.11)、[esbuild registry](https://registry.npmjs.org/esbuild/0.25.12)。Vitest 與 mocker 的 Vite 範圍接受 6.x；本機 Node **24.19.0** 符合相關 engines。CI 的 Node 20 已 EOL，因此 PR checks 與 main build/deploy 改為受支援 **Node 24 LTS**，保留原本 PR 唯讀權限與只從 main 部署的限制。[Vite 支援政策](https://vite.dev/releases)、[Node 官方支援狀態](https://nodejs.org/en/about/previous-releases)

## 保留的首次失敗與安裝方式

第一次使用既有 **npm 10.8.2 + Node 24.19.0** 安裝，**exit 1**，Arborist `#loadPeerSet` 報 `Cannot read properties of null (reading 'edgesOut')`。當時沒有產生已成功升級的 lockfile，失敗紀錄完整保留；沒有把失敗當成完成或以 peer／audit bypass 掩蓋。

依官方 [npm 11.18.0 registry](https://registry.npmjs.org/npm/11.18.0) 準備獨立臨時工具，驗證 tarball SHA-512 integrity 與 Node engines，未覆蓋既有工具或全域安裝。手動限定兩個直接版本後，以 **npm 11.18.0** 正常 `npm install` 成功 **exit 0**；其後完整 audit、相依樹與乾淨 `npm ci` 均成功。沒有使用 `--force`、`--legacy-peer-deps`、`--ignore-scripts`、audit 忽略或轉接相依直接加裝。

npm 11 有未登錄 allow-scripts 提示；未壓制警告，`ignore-scripts=false`，esbuild 0.25.12 的 postinstall 在實際 log 中已執行 **code 0**。建置另有既有超過500kB的 chunk size 警告，沒有為消除警告而改遊戲架構。
