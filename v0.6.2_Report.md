## 2. Engineering Changes & Technical Implementation

### A. Coordinate Mapping Helper (`getCanvasClickPoint`)
- Implemented a unified coordinate resolution helper in `tests/e2e/run-e2e.cjs`:
  - Retrieves canvas bounding client rect and scale factors (`scaleX = rect.width / game.scale.width`).
  - Evaluates `obj.getWorldTransformMatrix()` to account for containers and hierarchies.
  - Distinguishes between fixed screen UI elements (`scrollFactor === 0`) and camera world objects (`scrollFactor !== 0`).
  - Correctly transforms world points into camera viewport coordinates:
    `screenX = cam.width / 2 + (wx - (cam.scrollX + cam.width / 2)) * cam.zoom`
    `screenY = cam.height / 2 + (wy - (cam.scrollY + cam.height / 2)) * cam.zoom`
  - Maps camera viewport coordinates to browser client coordinates via canvas scale and offset.

### B. Camera Stabilization & Scene Hygiene
- In `src/scenes/GameScene.ts`:
  - `gameOver()`: Stoppped camera follow (`this.cameras.main.stopFollow()`) and zeroed player velocity (`this.player.head.setVelocity(0, 0)`) so the game over UI remains completely static.
  - `levelClear()`: Stopped camera follow and zeroed player velocity on level completion.
  - `victory()`: Stopped camera follow and zeroed player velocity.
  - `hardReset()`: Safely guarded camera access (`if (this.cameras && this.cameras.main)`) and resumed camera follow (`this.cameras.main.startFollow(this.player.head, true, 0.1, 0.1)`).

### C. Physical UI Interaction Acceptance (Test AW)
- Removed all synthetic `.emit('pointerdown')` fallbacks across:
  - Game Over -> `playAgainBtn` -> `PrepScene` (Level 1, default prep value 5).

  - Level 4 Clear -> `playAgainBtn` -> `PrepScene` (Level 4).
