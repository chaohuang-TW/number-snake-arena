## Key Changes & Resolutions

### 1. Mobile Leaderboard Layout & Overlap Resolution
* **Issue**: On narrow mobile portrait viewports (`width <= 450px`, e.g., 390x844, 430x932), the leaderboard panel (`width = 156px`, `x ≈ 222–262`) overlapped the top boost bar (`x ≈ 95–295`, `y ≈ 20–40`).
* **Fix**: In `src/ui/LeaderboardPanel.ts`, dynamically set `posY = w <= 450 ? 148 : 12`. On mobile viewports, the panel is placed directly beneath the top HUD stack (`y ≈ 20–130`) and above bottom touch controls (`y ≈ 664–764`), leaving ample clearance and eliminating any bounding overlap.

### 2. Pure Geometric Bounding & Overlap Utilities
* **Implementation**: Created `src/utils/layout.ts` exporting:
  * `RectBounds` interface (`x`, `y`, `width`, `height`).
  * `rectsOverlap(a: RectBounds, b: RectBounds): boolean` checking 2D axis-aligned bounding box intersections.
  * `isRectInside(inner: RectBounds, outer: RectBounds): boolean` verifying strict viewport containment.
* **Component Bounds Integration**:
  * `LeaderboardPanel.getBounds(): RectBounds`
  * `HUD.getHPBounds()`, `getScoreBounds()`, `getBestBounds()`, `getMagnetHUDBounds()`, `getBoostBarBounds()`, `getBoostButtonBounds()`, `getMagnetButtonBounds()`
  * `VirtualJoystick.getBounds(): RectBounds`
  * `GameScene.getLayoutBounds()` unifying all component bounding rectangles for layout assertions.
* **Unit Tests**: `tests/layout.test.ts` with 7 pure unit tests covering overlap detection, containment, edge abutment, and zero-dimension handling.

### 3. Clean Production Routing
* **Removal of Test URL Branches**: Removed `window.location.search.includes('e2e=1')` and `debug=1` condition branches from visible UI buttons:
  * `MenuScene`: Level card `START` buttons unconditionally route to `PrepScene`.
  * `GameScene`: Game Over `PLAY AGAIN`, Level Clear `REPLAY LEVEL`, `NEXT LEVEL`, and Level 4 `PLAY AGAIN` unconditionally route to `PrepScene`.
* **Testing Hygiene**: Canonical regression tests needing direct `GameScene` start invoke `window.__PHASER_GAME__.scene.start('GameScene', ...)` directly via test harness, keeping production button code completely clean.

### 4. Real UI Acceptance Test Coverage (`tests/e2e/run-e2e.cjs`)
* **Test AU**: Real pointer click on Menu Level 1 `START` button -> transitions to `PrepScene`.
* **Test AV**: Real pointer clicks on Prep value cards (`5`, `7`, `10`), visual selection verification (fill & stroke colors), and real click on `START LEVEL`.
* **Test AW**: Real pointer clicks on Game Over `PLAY AGAIN`, Level Clear `REPLAY LEVEL`, `NEXT LEVEL` (L1->L2->L3->L4), and Level 4 `PLAY AGAIN`.
* **Test BB**: Responsive arena layout validation on all 7 target viewports (`390x844`, `430x932`, `768x1024`, `834x1194`, `1024x1366`, `1366x768`, `1920x1080`), asserting via `rectsOverlap` that the leaderboard does not intersect HP, Score, Best, Magnet HUD, Boost bar, Boost button, Magnet button, or Joystick. Real touch interactions (magnet tap, boost hold, joystick drag) verified in touch context.
* **Test BC**: Clean production URL routing (no query parameters) verifying Menu -> Prep -> Game navigation with readonly API.
